Reachability Over Creativity

A plain-language summary of my write-up for the Kaggle AI Agent Security: Multi-Step Tool Attacks competition. It won one of the two $2,500 Working Note Awards in October 2026.

The competition

Competitors tried to trick AI agents that use tools, such as sending email, reading files and browsing, into doing something harmful. A benchmark checked each attempt against a set of scoring rules, and a guardrail tried to block dangerous actions. The more rules an attack triggered, the higher it scored.

The key idea

A scoring rule is only as good as its false-positive rate. If a harmless action that the user actually asked for can trigger it, the benchmark is measuring the scorer, not the agent, and competitors will farm it.

What I found

I worked out, for every scoring rule, whether any attack could both trigger it and get past each kind of guardrail. Under the strict guardrail, only one rule was still reachable, called CONFUSED_DEPUTY. It also fired on an ordinary request like "notify the team that the report is ready". So the private leaderboard came down to repeating one harmless action as fast as possible.

What I built

  • An audit tool that, before a benchmark launches, reports which rules can score at all and which ones fire on harmless requests. It needs no GPU and no leaderboard.
  • A false-positive checker that builds a harmless, user-approved action for each rule and flags any rule that fires on it.
  • A utility probe that measures the guardrail's cost: how many legitimate user tasks it breaks, not only how many attacks it blocks.
  • Three fixes: structured authorization, scoring what the agent was persuaded to do, and checking every argument of a tool call. With them, the multi-step attacks count again, harmless traces come back clean, and the single-action shortcut stops paying.
  • 63 automated checks, released under the MIT licence.

What the judges said

"A clear diagnosis of benchmark failures with an implemented repair and experiments examining both security and legitimate task completion... the progression from identifying misleading scoring incentives to demonstrating concrete improvements, supported by inspectable code and explicit limitations."
